# Internationalization

Use for localized routes, root locale, fallback content, UI strings, RTL languages, and locale-aware components.

Source docs: `guides/i18n.mdx`, `reference/configuration.mdx#locales`, `docs/astro.config.mjs`, `src/content/i18n/*.json`.

## Configure Locales

Prefixed default locale:

```js
starlight({
  title: 'My Docs',
  defaultLocale: 'en',
  locales: {
    en: { label: 'English' },
    'zh-cn': { label: 'Simplified Chinese', lang: 'zh-CN' },
    ar: { label: 'Arabic', dir: 'rtl' },
  },
})
```

Content layout:

```txt
src/content/docs/
  en/index.md
  ar/index.md
  zh-cn/index.md
```

## Root Locale

Use `root` to serve the default language without a path prefix:

```js
starlight({
  title: 'My Docs',
  defaultLocale: 'root',
  locales: {
    root: { label: 'English', lang: 'en' },
    'zh-cn': { label: 'Simplified Chinese', lang: 'zh-CN' },
  },
})
```

Content layout:

```txt
src/content/docs/
  index.md
  getting-started.md
  zh-cn/
    index.md
    getting-started.md
```

For a monolingual non-English site, set only `root` with the desired `lang`.

## Fallback Content

Starlight expects matching paths across languages. Missing translations fall back to the `defaultLocale` content and show a notice.

Example:

```txt
src/content/docs/en/about.md
src/content/docs/fr/about.md       # translated
src/content/docs/de/about.md       # missing -> fallback if configured
```

Use fallback intentionally for progressive translation, but verify users see the expected notice and language switcher behavior.

## Translate Site Title

```js
starlight({
  title: {
    en: 'My Docs',
    'zh-CN': 'My Docs in Chinese',
  },
  defaultLocale: 'en',
  locales: {
    en: { label: 'English' },
    'zh-cn': { label: 'Simplified Chinese', lang: 'zh-CN' },
  },
})
```

Object keys are BCP-47 tags, not necessarily directory keys.

## Translate UI Strings

Configure the `i18n` collection:

```ts
import { defineCollection } from 'astro:content';
import { docsLoader, i18nLoader } from '@astrojs/starlight/loaders';
import { docsSchema, i18nSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({ loader: docsLoader(), schema: docsSchema() }),
  i18n: defineCollection({ loader: i18nLoader(), schema: i18nSchema() }),
};
```

Add files in `src/content/i18n/`:

```txt
src/content/i18n/fr.json
src/content/i18n/zh-CN.json
```

Translate values, not keys:

```json
{
  "search.label": "Search",
  "tableOfContents.onThisPage": "On this page",
  "page.editLink": "Edit page"
}
```

Pagefind and Expressive Code UI strings can also be translated in the same JSON files using their documented keys.

## Extend Translation Schema

```ts
import { z } from 'astro/zod';

i18nSchema({
  extend: z.object({
    'custom.label': z.string().optional(),
  }),
})
```

The official Starlight docs extend i18n schema with an optional `component.preview` string.

## Using UI Translations

In Starlight components, use the route local translation helper:

```astro
---
const label = Astro.locals.t('search.label');
---
```

For plugin code, see [plugins.md](plugins.md) for `injectTranslations()` and `useTranslations()`.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Default language has `/en/` prefix unexpectedly | Use `root` locale or remove `defaultLocale` when root is default. |
| `root` locale language metadata wrong | Set `lang` explicitly on `root`. |
| UI string not translated | `i18n` collection configured, filename uses BCP-47 tag, key exists. |
| Fallback page unexpected | Missing localized page with matching path. |
| RTL layout wrong | Locale has `dir: 'rtl'`. |
