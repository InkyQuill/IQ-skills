# Content Pages and Collections

Use for docs pages, custom pages, content collections, schema extension, and route derivation.

Source docs: `guides/pages.mdx`, `manual-setup.mdx`, `reference/configuration.mdx`, `reference/frontmatter.md`, `src/content.config.ts`.

## Content Pages

Starlight content pages live in `src/content/docs/` and support Markdown and MDX by default.

```txt
src/content/docs/index.md                 -> /
src/content/docs/hello-world.md           -> /hello-world/
src/content/docs/reference/faq.mdx        -> /reference/faq/
```

Use subfolders to create route segments and to drive autogenerated sidebar groups.

## Required Collection Config

Current Starlight docs use `src/content.config.ts`:

```ts
import { defineCollection } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({
    loader: docsLoader(),
    schema: docsSchema(),
  }),
};
```

For i18n UI strings, add:

```ts
import { i18nLoader } from '@astrojs/starlight/loaders';
import { i18nSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({ loader: docsLoader(), schema: docsSchema() }),
  i18n: defineCollection({ loader: i18nLoader(), schema: i18nSchema() }),
};
```

If the local project uses legacy `src/content/config.ts`, follow its convention unless migrating is the task.

## Loaders

`docsLoader()` loads local Markdown, MDX, and Markdoc files from `src/content/docs/`. Files starting with `_` are ignored.

`i18nLoader()` loads JSON and YAML files from `src/content/i18n/`. Files starting with `_` are ignored.

Custom ID example:

```ts
docsLoader({
  generateId: ({ entry }) => entry.split('.').slice(0, -1).join('.'),
})
```

Use custom IDs sparingly because route and sidebar expectations change.

## Schemas

`docsSchema()` parses docs frontmatter. Extend it; do not replace it.

```ts
import { z } from 'astro/zod';

docsSchema({
  extend: z.object({
    description: z.string(),
    category: z.enum(['tutorial', 'guide', 'reference']).optional(),
  }),
})
```

For Astro's `image()` helper, use a function form if needed by current Astro docs.

## Custom Pages

Use `src/pages/` for pages outside the docs collection: custom layouts, generated routes, alternate data sources.

To reuse Starlight layout:

```astro
---
import StarlightPage from '@astrojs/starlight/components/StarlightPage.astro';
import AnchorHeading from '@astrojs/starlight/components/AnchorHeading.astro';
---

<StarlightPage frontmatter={{ title: 'My custom page' }}>
  <AnchorHeading level="2" id="learn-more">Learn more</AnchorHeading>
</StarlightPage>
```

Custom `StarlightPage` caveats:

- `slug` is not supported; URL comes from `src/pages/` routing.
- `editUrl` must be a URL if used.
- `sidebar` frontmatter is not available for autogenerated sidebar groups because the page is not in the docs collection.
- `draft` shows a notice but does not automatically exclude custom pages from production builds.

Useful `StarlightPage` props:

| Prop | Purpose |
| --- | --- |
| `frontmatter` | Required title and page metadata. |
| `sidebar` | Custom sidebar for that custom page. |
| `hasSidebar` | Override sidebar visibility. |
| `headings` | Provide TOC headings. |
| `dir`, `lang` | Override direction/language. |
| `isFallback` | Mark fallback i18n content. |

Use [route-data-overrides.md](route-data-overrides.md) for deeper route data customization.
